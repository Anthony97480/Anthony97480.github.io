Projet d'initiation à la recherche

  • Réalisé en 2026.
  • But/Consigne:
    Proposer une solution intelligente, qui esploite les avancée de l'intelligence artificielle, permettant d'accompagner et de facilité les déplacement des personnes TSA (Trouble du Spectre de l'Autisme).
  • Ce qui a été réalisé:
    Dans un groupe de 7 étudiant, il a été décidé, suite au résultat de l'état de l'art réaliser (ci-joint), de concevoir une application mobile d'aide à la navigation en prenant en compte différent paramètre pouvant engendré du stresse chez les individus afin de un itinéraire pour un point de départ et une destination donnée.
    1. Description: Projet réalisé en coopération entre l'INSA et le LASS-CNRS de Toulouse. L'application mobile du nom de ASDIA (Autisim Spectrum Desorder Itinary Asistante) est composé d'un front-end, application mobile codé en kotlin et d'un back-end composé de deux serveur, un FastAPI python afin de réceptionner les requête et parser correctement les JSON et de récupérer via des API les information de la ville de Toulouse concernant les facteur pouvant engendré du stresse chez un individus. Ce serveur est en communication avec un autre serveur en C++ cette fois-ci, servant uniquement au calcule des itinéraire à l'aide d'un algorithme dijkstra.
      Le principe de l'application est de récolté les donnée de l'utilisation via un quiz présent uniquement au lancement de l'application, afin de récupérer les préférences des utilisation en fonction de situation donnée, pour fournir ces information de stresse au serveur afin de calculer l'itinéraire le plus adapter à l'utilisateur. Et de permettre à l'utilisateur de rentré une demande d'itinéraire et de la ressevoir en l'affichant sur une carte.
      Pour l'instant tous les itinéraire calculer ne fonctionne que sur la ville de Toulouse, étant donnée que toutes les information sont récupére via les API de cette même ville uniquement.
    2. Technologies: Android studio, FastAPI, Git, Jira et UML/Modèle relationnel.
    3. Langages: C++, Kotlin et Python.
    4. Mon rôle: J'ai été attribuer à la réalisation de la partie front-end de l'application en Kotlin et à une partie de la communication du front-end et du back-end via des appels http du coté applicatif afin d'envoyer et de réceptionner les JSON contenant les information des itinéraire calculée.
  • Rapport du projet: Article scientifique

Projet Système informatique

  • Réalisé en 2026.
  • But/Consigne:
    Réaliser par groupe de deux un compilateur pour une portion réduite du langages C (oppération arithmétique et logique de base, boucle while, condition if else, print) ayant en sortie le langage assembleur/binaire(sur 32bit) correspondant au code C d'entré. Puis réaliser sur un FPGA une architecture RISC avec 5 couche de pipeline et exécuté le code C à l'aide de la sortie binaire produire par le compilateur sur le FPGA.
  • Ce qui a été réalisé:
    1. Description:
      1. Compilateur: Pour le compilateur, il a été décidé de réaliser une implémantion orienté regitre et donc, toutes les variable du code une fois parsé sont enregistrer dans une table des symbole et les indexes de cette table sont utiliser afin de générer la table assembleur (qui est un liste chainé représentant chacune des instruction que devra réaliser notre processeur) qui à la fin de du parsage du code C sera convertie en binaire et retournée dans un fichier. Le contenu de se fichier sera ensuite utiliser Par le processeur RISC.
        Il a également été décidé de tenir trace des élément dans la table des symbole avec deux variable distincte afin de pouvoir faire la différence entre les variable du code et les variable temporaire nécessaire au oppération assembleur. Les deux liste chainé représentant les table assembleur et des symbole, sont ainsi réculièrement modifier:
        1. Pour la table assembleur: pour tenir tace des jump dans le cas des condition et boucle.
        2. Pour la table de symbole: afin de supprimer les variable temporaire inutile après parsage mais aussi supprimer les variable en tenant en compte leur profondeur afin d'empêcher l'utilisateur d'utiliser une variable déclarer dans une structute à l'extérieur de celle-ci.
      2. Processeur RISC: Composer d'un ALU, d'un banc de mémoire, d'un banc d'instruction, d'un banc de registre, et des étage du pipeline afin de relier chacun des différent composant de l'architecture. De nombreuse simplification ont été réaliser dans le code étant donnée le nombre d'instruction et le nombre de bits sur lequels étaient les élément, les signaux vhdl sont le plus souvent sur 4 à 8 bits.
        Par manque de temps, les étages du pipeline, ne prennent en compte que les oppération assembleur COP et AFC.
    2. Technologies: Vivado, Git, FPGA.
    3. Langages: C, Lex, Yacc, VHDL.
  • Rapport du Projet: Rapport
  • Présentation: Site web de présentation

ChatSystem

  • Réalisé en 2025.
  • But/Consigne:
    Par groupe de 2, réaliser une application en Java, permettant la communication entre différents utilisateurs sur un réseau local sans utiliser de serveur.
  • Ce qui a été réalisé:
    1. Description: L'application est capable de détecter sur un réseau local les autre utilisateur connecter à celle-ci via l'envoie d'une requête UDP en broadcast et celle-ci constitue ainsi une liste des utilisateur connecter afin de permettre à l'utilisateur de l'application de savoir qui est connecter et de pouvoir communiquer via l'envoie de message TCP au autres utilisateur présents sur l'application sur le réseau. L'application permet aux utilisateurs de pouvoir de se connecter et se déconnecter de celle-ci (pour être visible ou non sur le réseau) et empêche toute utilisateur d'avoir deux même nom d'utilisateur ou d'utiliser un langage ingurier pour se connecter.
      L'application est ainsi à la fois un serveur et un client TCP. L'application met en place une base de donnée SQL en local permettant d'enregistrer les utilisateur connue (et plus exactement leur ID unique) ainsi que leur conversation afin que même si un utilisateur change de pseudo, l'historique de conversation est concerver. Cependant cette méthode local imposé présente des limite, si un utilisateur utilise un autre ordinateur, celui-ci ne possédant pas la base de donnée local créer par l'application, toutes les données sont donc inaccessible.
    2. Technologie: Maven, SQLite, Jira, UML/Modèle relationnel et Git
    3. Langages: Java et SQL
